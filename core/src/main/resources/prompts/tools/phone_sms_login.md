Fill a newly received SMS login code locally, only when the user explicitly asked to log into this app. First open its login page, enter the user's account, then identify the exact resourceId of one native code editor and sendButtonId of the native send/resend button. Do not request a code beforehand. The host asks the user on-device to authorize this attempt and specify the exact sender, SMS signature and account marker; none of those private values or the SMS/code are returned to you. Settings must be enabled and Android RECEIVE_SMS granted. Messages must contain that exact service signature and account marker and explicitly be for login; payment, registration, recovery and ambiguous messages are refused. Only SMS received AFTER on-device consent is accepted: the host registers its listener before requesting a code once. A filled status confirms only input, not login success. Once the private flow starts, phone observations and previews stay hidden for this run: hand any remaining step to the user and finish. On any failure offer manual takeover; never read SMS through another app, notifications, screenshots, shell, sandbox or MCP to work around a refusal. Never ask the user for a code in chat. No support for WebViews, split code fields, copied profiles or unattended/child/remote tasks.
